Design rule

Reference the vault. Do not become the vault.

Production Desk should receive the minimum aggregate information needed for staff decisions while sensitive donor and payment data stays in the system designed to protect it.

For technical review

Where this prototype must be broken apart.

01Authentication

Production needs server-verified sessions, secure recovery, MFA policy, lockout/rate limits, and no secrets in browser code.

02Authorization

Church scope and role controls must be enforced on the server. Hiding a button is never permission.

03Publication boundary

Private records and public projections should be distinct. Only reviewed fields cross into the public site.

04File handling

Uploads need type/size validation, malware scanning, private object storage, controlled URLs, and retention rules.

05Audit & recovery

Every publish, override, deletion, permission change, and restore should have an actor, timestamp, prior value, and recoverable history.

06Sensitive domains

Finance, pastoral care, children/youth, donor identity, and credentials need stronger separation than ordinary public content.
